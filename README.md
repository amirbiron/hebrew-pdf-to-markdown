# PDF עברי ל-Markdown

ממיר PDF בעברית ובעברית-אנגלית מעורבת ל-Markdown, שמסמן בבירור כל עמוד שהוא לא בטוח בו. הגרסה הראשונה מתוכננת כדף באתר: מעלים קובץ, מקבלים Markdown, ולצד כל עמוד שסומן מופיעה אזהרה עם הסיבה.

## למה

כל ספריות החילוץ שנבדקו (pdf_oxide, poppler, PyMuPDF, pypdfium2, Unstructured) שוברות עברית בחלק מהקבצים: מילים הפוכות, אנגלית הפוכה בתוך עברית, פיסוק שקופץ לתחילת השורה, מספרים שזזים בין עמודות בטבלה. והן עושות את זה בשקט, בלי שום סימן שמשהו לא בסדר.

הממצא המרכזי מהבדיקות: **הקבצים עצמם תקינים.** בכל 12 קובצי הבדיקה, משמונה תוכנות יצירה שונות, העברית שמורה בסדר הנכון. מה ששובר אותה הם הקוראים, שמנסים "לתקן" סדר ומקלקלים. לכן הגישה היא קורא אחד (pypdfium2) שבונה כל שורה לפי מיקום האותיות על הדף, ובדיקות שמסמנות עמודים לא ודאיים.

## מבנה

| תיקייה | מה יש בה |
|---|---|
| `hebrew_pdf/` | בונה השורות: קריאת האותיות מ-pypdfium2 (`chars.py`), קיבוץ לשורות ובניית הטקסט (`lines.py`), הרווחים לפי הפערים בעמוד (`spacing.py`), הסדר הלוגי של שורה לפי אלגוריתם הכיוון של Unicode וכיוון הפסקה לפי המסמך (`logical_order.py`), הצורה של סוגר לפי מה שמצויר בעמוד (`bracket_shapes.py`), והבדיקות העקיפות (`indirect_checks.py`) |
| `prototype/` | האב-טיפוס שממנו התחיל `hebrew_pdf`, כמו שהיה. נשאר כתיעוד של נקודת ההתחלה, ולא משתנה |
| `testset/pdfs/` | סט הבדיקה הקבוע: 12 קובצי PDF אמיתיים, ועוד קובץ טבלאות שנבנה ממקור ידוע |
| `testset/README.md` | פירוט הקבצים: איזו תוכנה יצרה כל אחד ומה מיוחד בו |
| `testset/labels.md` | 40 שורות מתויגות: מה הכלי הוציא מול הטקסט הנכון לפי העמוד. רק שורה בסטטוס "מאושר" נספרת. גבול בין תאים בשורה נכתב `<br>` |
| `testset/ground_truth/` | דפי תשובות לקובצי הטבלאות: הטקסט של כל תא, שנגזר מהמקור. מושווים תא מול תא, בלי תיוג ביד |
| `testset/sources/` | המקור (Markdown) שממנו נבנה כל קובץ טבלאות |
| `tools/` | `build_table_pdf.py`: בונה מהמקור את קובץ הטבלאות ואת דף התשובות שלו |
| `testset/report.md` | הדוח של מערך הבדיקה. נכתב מחדש בכל הרצה; לא עורכים אותו ביד |
| `harness/` | מערך הבדיקה. הקורא נקרא דרך פונקציה אחת, `read_pages` ב-`harness/reader.py`: כדי לבדוק קורא אחר משנים רק אותה. `display_check.py` בודק כל שורה בסט: האם הפלט, כשמציגים אותו בפסקה עברית, נראה כמו השורה בעמוד. `label_order.py` בודק את הסדר של כל תיוג באותה דרך, ו-`tables.py` משווה את הפלט לדפי התשובות של הטבלאות |
| `tests/` | בדיקות של מערך הבדיקה עצמו, כולל בדיקה שקורא מקולקל בכוונה מוריד את התוצאה |

## הרצה

```bash
pip install -r requirements-dev.txt   # הקורא עצמו צריך רק את requirements.txt
python prototype/hebrew_pdf_prototype.py testset/pdfs/mentoros-overview_weasyprint.pdf
python prototype/hebrew_pdf_prototype.py --score testset/pdfs
python -m harness                      # מערך הבדיקה: כותב את testset/report.md
python -m unittest discover -s tests   # הבדיקות של מערך הבדיקה
python tools/build_table_pdf.py testset/sources/env-vars.md /tmp/env.pdf /tmp/env.truth.json   # בנייה מחדש של קובץ הטבלאות
```

**להשוות לפני ואחרי שינוי:** הדוח דטרמיניסטי (בלי תאריכים ובלי זמני ריצה), אז מריצים `python -m harness` אחרי השינוי ומסתכלים על ה-diff של `testset/report.md` ב-PR. כל שורה שהשתנתה בו היא שינוי אמיתי בתוצאה. לדוח נפרד: `python -m harness --output /tmp/after.md`.

## מצב

בונה השורות נמצא ב-`hebrew_pdf/`, וכל תיקון בו נמדד במערך הבדיקה: כשל במיקום של אות לא עובר בשקט, רצפים מעורבים של עברית ואנגלית מסודרים לפי אלגוריתם הכיוון של Unicode, סוגריים נקבעים לפי הצורה המצוירת בעמוד, כיוון הפסקה נקבע לפי המסמך כולו (גם לשורה בלי עברית), והרווחים נקבעים לפי הפערים בעמוד ולא לפי תווי הרווח שבקובץ. כל 40 השורות ב-`testset/labels.md` מאושרות, 26 מהן יוצאות זהות, והתוצאה העדכנית בכל רגע היא `testset/report.md`. מערך הבדיקה בודק גם את הסדר של כל תיוג (37 מתוך 40 עוברות; שלוש השורות האחרות הן טקסט שלא קיים בקובץ), ומודד את קובץ הטבלאות תא מול תא מול דף התשובות שלו. השלבים הבאים לפי מסמך האפיון: טבלאות וגבולות בין רכיבים, ציון וסימון של עמודים, ובסוף הדף באתר.
